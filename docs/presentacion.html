Proyecto final de programación

MercadoOS

Sistema de punto de venta, inventario y reportes para supermercados. Avance de análisis, diseño y prototipo funcional.

El problema

El súper pequeño opera a ciegas

  • Stock en cuaderno o Excel: se vende lo que ya no hay.
  • Caja sin arqueo: no se sabe cuánto debió quedar.
  • Precios distintos según el cajero.
  • Cero reportes para decidir qué comprar.

Objetivo

Operar el negocio, no solo listar productos

Un sistema web donde el flujo sea: entra mercadería, se controla inventario, se vende en caja, se cierra y se reporta. Listo para la clase y con camino a producto vendible.

Alcance

Tres fases, promesas honestas

Fase 1 — MVP

Login, productos, inventario, caja, ventas y reportes. Esto es el prototipo de hoy.

Fase 2 — Completo

Compras, proveedores, clientes, cierre de caja, devoluciones y caducidad.

Fase 3 — Vendible

Multi-sucursal, factura fiscal, auditoría, backup e instalador.

Fase 1

Módulos imprescindibles

  • Usuarios y roles — contraseñas con hash.
  • Catálogo — código de barras, precio, ISV, stock mínimo.
  • Inventario — existencias reales y alerta de stock bajo.
  • Caja (POS) — carrito, cobro, cambio y descuento automático de stock.
  • Ventas y reportes — día, más vendidos, total por cajero.

Fase 2 y 3

De proyecto de clase a producto

Completo (Fase 2)

  • Proveedores y órdenes de compra
  • Cierre de caja y devoluciones
  • Clientes, promociones, lotes

Vendible (Fase 3)

  • Multi-sucursal y multi-caja
  • Ticket / factura fiscal
  • Auditoría, backup, Docker

Seguridad operativa

Arquitectura de negocio

No es un CRUD: es un ciclo

Proveedor→ Compras→ Inventario→ Caja→ Ventas→ Reportes

Si el stock no baja al vender, el sistema miente. El prototipo ya descuenta existencias en cada venta.

Datos

Modelo mínimo

Hoy

Rol, Usuario, Categoria, Producto, Venta, DetalleVenta, MovimientoInventario (kardex).

Después

Proveedor, Compra, Cliente, Caja, CierreCaja, Promocion, Lote.

Tecnología

Stack del prototipo

  • Node.js + Express + EJS — backend MVC, fácil de explicar.
  • SQLite — cero servidor de BD; migrable a MySQL/PostgreSQL.
  • Sesiones + bcrypt — autenticación real, no usuarios en texto plano.
  • Interfaz web — se muestra en el navegador, lista para vender después.
